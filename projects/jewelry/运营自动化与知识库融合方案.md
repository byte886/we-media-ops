# 泉泉方法论 × 运营平台融合方案（知识库 + 自动化）

> 依据《泉泉运营方法论_深度梳理》设计
> 规划日期：2026-10-12
> 目标：把泉泉方法论内化为**可查询的知识库 + 可执行的自动化流水线**，不再靠人脑记、不靠临时翻 PDF

---

## 一、总体设计：三库一流水线

```
┌─────────────────────────────────────────────────────┐
│  运营知识库（projects/jewelry/knowledge-base/）        │
│  ├── 01_赛道与用户洞察     ← 洞察报告+对标拆解提炼      │
│  ├── 02_选题库            ← 200标题改写+翡翠适配        │
│  ├── 03_脚本与视频框架      ← 黄金3秒+结尾模板           │
│  ├── 04_合规库            ← 禁用词+话术模板+100细节     │
│  ├── 05_对标库            ← 9账号+爆款笔记拆解表        │
│  └── 06_复盘工具          ← 5张表的使用SOP             │
└─────────────────────────────────────────────────────┘
                        ↓ 供能
┌─────────────────────────────────────────────────────┐
│  自动化流水线（每条内容走一遍）                          │
│  选题推荐 → 脚本生成 → AI味检查 → 合规检查 → 发布 → 复盘  │
└─────────────────────────────────────────────────────┘
```

## 二、知识库怎么建（结构设计）

### 落位：`projects/jewelry/knowledge-base/运营方法库/`

```
运营方法库/
├── README.md                    # 索引：什么时候查哪个文件
├── 01_赛道洞察.md                # 平台数据/人群/关键词/冷启动路径
├── 02_用户画像与痛点.md          # 画像/需求/内容偏好/趋势
├── 03_选题池.md                 # 从200标题筛出翡翠适用，分主题维护
├── 04_视频脚本框架.md            # 黄金3秒开头模板/结尾模板/四坑
├── 05_合规速查.md               # 禁用词表/合规话术模板/100细节索引
├── 06_对标账号库.md             # 9个账号拆解（我们已调研的）+ 爆款笔记
└── 07_数据复盘SOP.md            # 五张表怎么填、多久填一次、看什么
```

> 素材源不动：泉泉资料宝典（14MD+PDF+xlsx）保留为**原始素材**；运营方法库是**提炼后的活用法**。两者分离，避免改原始资料。

## 三、自动化怎么做（分四档，按投入产出排序）

### 档位1：立即可做（纯文档/表格，无开发）

| 自动化点 | 做法 | 产出 |
|---|---|---|
| 选题推荐 | 从03_选题池按"本周目的+节点"挑3-5条给AI排序 | 每天/每周选题建议 |
| 脚本初稿 | 脚本模板（docs/templates/每日脚本模板.md）+ 04视频框架 → AI生成初稿 | 脚本草稿 |
| 合规预检 | 05合规速查 + standards/合规检查清单.md → 发布前逐条过 | 合规通过/修改意见 |
| AI味预检 | standards/不AI化质量标准.md + sops/AI味检查SOP.md → 发布前过 | 去AI味意见 |

> 这四步当前就能跑：AI（我）作为执行者，读知识库 → 产出 → 过检。**不需要写代码**。

### 档位2：一周内可做（工具表启用）

| 自动化点 | 做法 | 产出 |
|---|---|---|
| 发布台账 | 启用 xlsx 的"自有账号分析表"结构，本地维护发布记录 | 每篇的选题/目的/数据 |
| 周复盘 | 每周日填"运营复盘表"（单篇+周汇总），AI 汇总结论 | 周报+下周调整 |
| 对标采集 | 用 trend-radar 定时拉对标账号笔记数/点赞（已有渠道矩阵） | 对标变化周报 |

### 档位3：可选（轻脚本）

| 自动化点 | 做法 | 依赖 |
|---|---|---|
| 选题自动生成 | 脚本读选题池+日历 → 输出每日选题 | 选题池建好后 |
| 合规自动检查 | 脚本跑禁用词表扫文案 → 标红 | 禁用词表完善后 |
| 数据自动抓取 | 小红书开放数据接口/手动导出 → 脚本填表 | 接口可行性待验证 |

### 档位4：暂不做（记录，不投入）

- 小红书自动发布（平台限制+封号风险，坚决不做）
- 自动回复私信（合规风险，只做话术模板人工套用）
- 投放自动化（预算未定，后置）

## 四、与现有体系的融合点

| 现有资产 | 融合方式 |
|---|---|
| D1-D7 珠宝冷启动脚本 | 用04视频框架重写结构（黄金3秒+结尾互动），保留现有内容 |
| 合规检查清单（standards/） | 并入05合规速查的100细节，补全 |
| 每日脚本模板（templates/） | 嵌入04框架：模板里加"开头三选一/结尾三选一"字段 |
| 对标账号（research/实地调研） | 填入06对标账号库，与泉泉拆解表对齐 |
| trend-radar（情报雷达） | 档位2启用：对标账号监控落地 |
| WORKFLOW 8步流水线 | 8步不变，每步的"输入"换成知识库对应文件 |

## 五、执行顺序建议

1. **本周**：建 运营方法库 七件套（把本次梳理的 07 文件 + 已有素材归位）→ 重写 D1-D7 结构
2. **下周**：启用发布台账 + 周复盘表；D1-D7 跑起来
3. **再下周**：对标采集接入 trend-radar；选题池进入循环维护
4. **持续**：每周复盘驱动选题池/脚本框架迭代，形成飞轮

## 六、风险与边界

- **不买泉泉课程/不引泉泉流量**：只吸收方法论，自主运营
- **不照抄200标题**：只借结构，内容必须是我们自己的（合规+原创要求）
- **合规优先**：任何自动化不碰"自动发布/自动私信"红线
- **飞书云文档并行**：另一窗口整理的运营资料入库后，本方案与之合并去重（以本仓库为执行真相，飞书为查阅副本）
